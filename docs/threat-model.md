# Threat model

Agent Comms coordinates cooperative principals sharing one filesystem and OS trust boundary. It defends against accidental conflicts, unauthorized governed operations, corrupted or reordered durable history, forged actor records without a matching key, interrupted writes, and unsafe checkpoint divergence.

It does not defend against a hostile administrator, kernel compromise, or a malicious process with unrestricted access to the same OS account and keyring — with one narrow, deliberate exception: granting the Orchestrator role and approving a HUMAN-tier approval require a second, passphrase-encrypted "elevated" key (`agent-comms agent elevate-key`, see docs/governance.md) whose passphrase is never written to disk and can only be supplied through a real interactive terminal, so a process with unrestricted keyring access still cannot complete those two specific transitions without it. That exception protects a live process riding on the human's OS-level access; it does not extend to a process that also captures the passphrase itself (e.g. a human typing it into a compromised or over-trusted agent's chat), nor to compromise of the *primary* key, which can still mint a fresh elevated key of its own. Everything else in this project remains governed by ordinary credential possession, not a stronger guarantee. Git remotes are recovery transport, not distributed locks. Human-tier policy is an auditable governance control, not biometric proof.
